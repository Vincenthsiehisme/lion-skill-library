# Strategy Case Report — Trigger & Output Evals

> v2.7.2 新增。本檔包含兩部分：
> 1. **Trigger eval queries**：should-trigger 與 should-not-trigger 範例，用來測 description 觸發精準度
> 2. **Output eval rubric**：完成報告後可用來檢核產出品質的客觀指標
>
> 用途：人工抽查 / `skill-evolve` 趨勢診斷的輸入 / `skill-review` 8-dim 審查時的對照基準。
> 邊界提醒：本 skill 與 `prd-writer`、`critical-reviewer`、`market-analyst`、`product-proposal` 觸發詞高度相鄰，下方 should-not-trigger 列出最容易混淆的鄰居案例。

---

## Part 1｜Should Trigger（應觸發本 skill）

### 明確觸發

| # | 使用者輸入 | 觸發理由 |
|---|-----------|---------|
| T01 | 「幫我做一份品牌案例報告，找三個近兩年台灣 D2C 品牌的 rebranding 案例」 | 明確要求多案例橫向比較 + 案例報告字眼 |
| T02 | 「我想做一份策略 deck，題目是『高端旅遊品牌如何重塑體驗價值』，要找 3 個案例」 | 策略 deck + 多案例 + 策略主題 |
| T03 | 「下個月要對主管做提案，需要月報級的競品策略拆解，三個品牌案例」 | 月報 + 提案素材 + 多案例 |
| T04 | 「幫我研究最近台灣零售業數位轉型的代表性案例，要做策略拆解」 | 多案例橫向研究 + 策略拆解 |
| T05 | 「找幾個 SaaS 品牌如何處理 PLG 到 SLG 轉型的案例給我」 | 「找幾個案例」+ 多案例橫向比較意圖 |

### 模糊但應觸發

| # | 使用者輸入 | 觸發理由 |
|---|-----------|---------|
| T06 | 「我想了解奢侈品產業最近怎麼做年輕化的，找幾個品牌的做法給我看」 | 雖未說「案例報告」，但「找幾個品牌做法」=多案例橫向研究 |
| T07 | 「下週要決定我們團體旅遊產品的視覺重塑方向，先做幾個品牌的功課」 | 提案前置研究 + 「先做幾個」=多案例 |
| T08 | 「ESG 議題在亞洲市場的品牌操作，幫我看 3-4 個值得學的做法」 | 多案例 + 萃取可借用做法（What to steal）意圖 |
| T09 | 「想找一些做得好的內容行銷案例，做月度策略分享用」 | 月報 + 多案例萃取 |
| T10 | 「電商品牌會員制度的幾個經典玩法，我要拿來提案參考」 | 多案例策略萃取 + 提案前置 |

## Part 2｜Should NOT Trigger（不應觸發；應走鄰居 skill 或不走 skill）

### 應走 prd-writer（產品需求 / 問題定義階段）

| # | 使用者輸入 | 為什麼不走本 skill |
|---|-----------|------------------|
| N01 | 「幫我寫團體旅遊出發團管理的 PRD」 | 明確 PRD 需求，走 prd-writer |
| N02 | 「使用者一直反映訂單流程很卡，但我不知道根本原因，幫我探索」 | 模糊問題定義階段，走 prd-writer 的 fuzzy front-end |
| N03 | 「為了這個新功能，我要做一份競品分析」 | 為「單一產品功能」做的競品比較，走 prd-writer 而非策略案例報告 |
| N04 | 「這個機會空間值不值得做，幫我評估」 | 單一機會評估，走 prd-writer |

### 應走 critical-reviewer（已有假設找佐證／反證）

| # | 使用者輸入 | 為什麼不走本 skill |
|---|-----------|------------------|
| N05 | 「我覺得我們應該轉型做訂閱制，幫我找案例證明這是對的」 | 已有明確假設找佐證，走 critical-reviewer。**對應 case-selection.md 前置退出條款** |
| N06 | 「審查一下這份提案，找盲點」 | 批判既有產出，走 critical-reviewer |
| N07 | 「devil's advocate 一下這個策略方向」 | 對單一假設做批判，走 critical-reviewer |
| N08 | 「給我第二意見，這份規劃哪裡有問題」 | 對既有規劃審查，走 critical-reviewer |

### 應走 market-analyst（金融 / 股市）

| # | 使用者輸入 | 為什麼不走本 skill |
|---|-----------|------------------|
| N09 | 「幫我出今天台股盤前報告」 | 金融市場報告，走 market-analyst |
| N10 | 「給我這檔股票的基本面分析」 | 股市分析，走 market-analyst |
| N11 | 「這個月的投資組合月報」 | 投資月報≠策略月報，走 market-analyst |

### 應走 product-proposal（單一團旅產品開案）

| # | 使用者輸入 | 為什麼不走本 skill |
|---|-----------|------------------|
| N12 | 「我想做一個北海道親子團，幫我評估開案可行性」 | 單一團旅產品開案，走 product-proposal |
| N13 | 「這條歐洲深度線值不值得排出來」 | 單一產品評估，走 product-proposal |

### 一般搜尋即可（不需走完整 case report 流程）

| # | 使用者輸入 | 為什麼不走本 skill |
|---|-----------|------------------|
| N14 | 「幫我找一篇關於 D2C 趨勢的文章」 | 純資料檢索，web search 即可 |
| N15 | 「這個案例是哪一年的？」 | 單一事實查詢 |
| N16 | 「Patagonia 的環保策略大概是什麼？」 | 單篇資訊摘要，不需走 6 個 phase |
| N17 | 「幫我整理這份新聞稿的重點」 | 單篇文獻摘要 |

## Part 3｜邊界判斷對照表（最容易混淆的句型）

### 「幫我研究」

| 子情境 | 走哪個 skill | 判斷依據 |
|-------|------------|---------|
| 「幫我研究幾個品牌怎麼做 X」 | strategy-case-report | 「幾個」=多案例橫向 |
| 「幫我研究 X 是不是個好方向」 | prd-writer / critical-reviewer | 已有假設要驗證 |
| 「幫我研究這個產業最近的趨勢」 | web search 即可 | 純資料檢索 |

### 「找幾個案例」

| 子情境 | 走哪個 skill | 判斷依據 |
|-------|------------|---------|
| 「找幾個案例做月度分享」 | strategy-case-report | 多案例策略萃取 |
| 「找幾個案例佐證我的提案」 | critical-reviewer | 為單一提案找佐證 |
| 「找幾個案例看看別人怎麼解這個產品問題」 | prd-writer | 為單一產品功能做競品比較 |

### 「策略 / 競品分析」

| 子情境 | 走哪個 skill | 判斷依據 |
|-------|------------|---------|
| 「策略 deck，3 個品牌的橫向比較」 | strategy-case-report | 多案例策略 deck |
| 「為這個新功能做競品分析」 | prd-writer | 為產品功能做的競品 |
| 「金融市場策略月報」 | market-analyst | 金融場景 |

## Part 4｜Output Eval Rubric（產出品質檢核）

> 完成報告後可用來檢核產出品質。供 `skill-evolve` 趨勢診斷與 `skill-review` 對照基準使用。

### 核心檢核項（所有報告必須通過）

| # | 檢核項 | 通過標準 | 不通過徵兆 |
|---|--------|---------|-----------|
| O01 | 三案視角結構說明完整 | Phase 3 Shortlist 明寫每案在視角結構中的角色 | 只有案例名稱，未說明視角分工 |
| O02 | 三欄結構誠實使用 | 每案 Why it lands 包含 confirmed / estimated / unknown 三欄 | 全部寫成 confirmed，或三欄混為一談 |
| O03 | Confirmed 來源元素完整 | 每筆 confirmed 含 source_title + publisher + date + URL + supports | 出現「官方資料」「媒體報導」等模糊指涉 |
| O04 | 品牌自述標注 | 來自品牌官網/新聞稿的數據明確標注 brand self-claim | 把品牌自述當成獨立驗證的事實 |
| O05 | 批判修正摘要存在 | 報告最末（Cross-case 之後、Source appendix 之前）有「批判修正摘要」段 | 段落不存在，或四個欄位全部寫「無」 |
| O06 | 批判修正摘要四欄齊全 | 每案至少 1 條實質修正內容（過度推論 / Confirmed 降級 / Unknown 邊界 / What to steal 降級） | 全部欄位空白或全寫「無」 |
| O07 | What to steal 可執行 | 每個方法含「具體第一步 + 邊界條件 + 前置條件」 | 只給泛用建議，無具體第一步 |
| O08 | 替換測試通過 | Insight 句換入 2-3 個同類品牌名後不成立 | 換入同類品牌名仍然成立=insight 太通用 |
| O09 | 風格規則遵守 | 無 emoji、無裝飾性圖示 | 章節標題或條列含 emoji |
| O10 | 模型有結構化呈現 | 被選用的模型以表格 / 矩陣 / 階梯式條列 / 流程文字化呈現 | 只寫模型名稱，無實際結構 |

### 進階檢核項（理想情況下應通過）

| # | 檢核項 | 通過標準 |
|---|--------|---------|
| O11 | 標題避免句型重複 | 整份報告「不是…是…」結構 ≤ 2 次 |
| O12 | 三案視角不重疊 | 任一案抽掉，另兩案說服力下降（不是同一個問題的三個版本） |
| O13 | Real problem 結構性力量可被指名 | 每個 problem 包含至少 2 個可被指名的結構性力量，非「市場競爭激烈」這類空話 |
| O14 | Tension 通過替換測試 | 真實矛盾，不是 observation |

## Part 5｜常見偽陽性與偽陰性（執行時注意）

### 偽陽性（不該觸發但可能誤觸）

- **「幫我做競品分析」單獨出現**：先確認是「為產品功能做的競品」（→ prd-writer）還是「策略型多品牌橫向比較」（→ 本 skill）。可用「這個分析最後是要拿來決定什麼」反問釐清。
- **「找幾個案例」單獨出現**：先確認意圖是「橫向萃取策略 insight」（→ 本 skill）還是「為單一假設找佐證」（→ critical-reviewer）。
- **「我要做月報」**：先確認是金融月報（→ market-analyst）還是策略月報（→ 本 skill）。

### 偽陰性（該觸發但可能漏觸）

- **「先做幾個品牌的功課」**：實質是多案例策略前置研究，應觸發。
- **「想看別人怎麼做 X」**：若指名「別人」=多個品牌，應觸發。
- **「下週提案前先看幾個成功案例」**：提案前置 + 多案例，應觸發。

## 維護規則

- 新增案例時，標注新增日期與情境來源（從哪次實際使用中發現的混淆案例）
- 每次 `skill-evolve` 趨勢診斷後，把新發現的偽陽性 / 偽陰性補入 Part 5
- 鄰居 skill description 改動時，重新檢視 Part 2 的對應條目是否仍正確
