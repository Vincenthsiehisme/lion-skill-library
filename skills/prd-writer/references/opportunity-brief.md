# Opportunity Brief

模糊階段的最終產出。整合機會探索和問題定義的結果，作為 prd-writer 的直接 input，或作為獨立的提案文件。

---

## 什麼時候輸出 Brief

滿足以下**至少一項**：
- 完成 Opportunity Snapshot（機會探索路徑）
- 完成 Problem Definition Canvas（問題定義路徑）
- 兩者都完成

未完成的部分標記 `[待補充]`，不阻止輸出，但需說明缺口。

## 完成門檻

**必填（缺一不能標「確認」狀態）**：
- 問題陳述：有用戶 + 情境 + 阻礙 + 影響，沒有夾帶解法
- HMW Statement：通過問題定義的完成門檻
- 至少 2 條有來源的證據
- **影響規模有具體數字或範圍**（不是「[待估算]」）

**建議填（沒填標記 [待補充] 但不擋）**：
- 待確認假設的驗證方式
- 競品現況

---

## 成熟度對應

| Brief 狀態 | 必填齊全度 | 成熟度 | 進 PRD 主流程的後果 |
|---|---|---|---|
| **確認** | 必填 4 件全齊 | **P2 達成** | 享受「跳問診」優惠（見銜接段） |
| **草稿** | 必填缺「影響規模」 | **P1.5** | 收到軟擋警告，Unknown Register 預期 ≥ 1 條 blocker |
| **草稿** | 必填缺問題陳述 / HMW / 證據 | **仍在 P1 以下** | 不應進 PRD 主流程，回去補 Canvas |

**影響規模為什麼是硬門檻**：沒有規模數字，「目標」與「成功指標」章節會大量出現 `[待確認門檻]`，Unknown Register 會炸，之後接 prd-spec 時 V8 Delivery Fit 不可判。寧可現在花 10 分鐘訪談 / 客服資料盤點 / 簡單 SQL 補上，不要把不確定性整批塞進 PRD。

---

## 銜接 PRD 主流程：硬跳過冗餘問診

Brief 完成（狀態 = **確認 / P2**）後，進 PRD 主流程時，**直接跳過已有答案的問診問題**：

| PRD 主流程的問題 | Brief 的對應欄位 | 動作 |
|---|---|---|
| 功能主要解決什麼問題？ | 問題陳述 | **自動帶入，不再問** |
| 目標使用者是誰？ | 目標用戶 | **自動帶入，不再問** |
| 預期影響範圍多大？ | 影響規模 | **自動帶入，不再問** |
| metrics 想看什麼？ | 策略連結 + HMW | 作為起點，仍會問細節 |
| 待確認假設 | 待確認的關鍵假設 | **整段帶入 Unknown Register 作為初始項** |

**若 Brief 狀態 = 草稿（P1.5）**：缺影響規模 → PRD 仍會問該欄位，且**輸出 P1.5 軟擋警告**（見 SKILL.md「成熟度警告」段）。

**動作提示給 PM**：
> 「Opportunity Brief 完成了（P2 / 確認）。進 PRD 主流程時會跳過前面問過的：功能解決什麼問題、目標用戶、影響規模——直接從 metrics 細節開始問。」

## Gotcha

- **Brief 不是 PRD 的縮水版**：Brief 裡不應該有功能列表、技術細節、或 acceptance criteria，這些是 PRD 主流程的工作
- **HMW 太早收斂成解法**：「HMW 做一個進度條」已經是解法，不是 HMW。Brief 裡的 HMW 必須還有設計空間
- **問題陳述夾帶解法**：「用戶需要一個更清楚的進度指示器」是解法，不是問題陳述
- **待確認假設要進 Unknown Register**：Brief 完成後帶進 PRD 主流程時，所有「待確認假設」必須同步入冊，不能只留在 Brief 裡
